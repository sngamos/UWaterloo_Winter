### Question 2
Digital Signatures ensure authenticity as the sender uses their private key to generate a digital signature from the message. Since the sender is the only person that has this private key, a valid signature proves that the message indeed originated from the sender. When the receiver uses the corresponding public key to verify the signature, a successful verification confirms that the message is authentic as it originates from the intended sender.  
Digital Signatures ensure Integrity as the digital signature is typically generated over a cryptographic hash of the message. If the message is altered in any way after it is signed, the computed hash on the receiver's end will differ from the original hash used to create the signature, causing the signature verification to fail, indicating that the message has been tampered with. Therefore it ensures integrity as, if the receiver is able to successfully verify the signature, it means that the message is the intended original message and has not been edited.

### Question 3
A system designer might choose a slower hash function like bcrypt over a faster one like SHA-256 for certain applications, particularly password storage, due to the following reasons:

- Resistance to Brute-Force Attacks:
    > Unlike SHA-256, which is designed for speed and efficiency, bcrypt is intentionally computationally intensive. This slowness is a critical advantage when hashing passwords because it slows down attackers attempting to crack them through brute-force or dictionary attacks. For example, an attacker using powerful hardware would take significantly longer to test password guesses against a bcrypt hash compared to a SHA-256 hash, making bcrypt more secure for this purpose.
- Built-in Salting and Key Stretching:
    > bcrypt automatically includes a salt—a random value added to each password before hashing—to prevent precomputed rainbow table attacks. It also performs key stretching, running multiple hashing rounds to increase the computational effort required. These features are built into bcrypt, ensuring consistent security without extra coding. In contrast, SHA-256 does not natively provide salting or stretching, so developers must implement these manually, which can lead to mistakes and vulnerabilities.
- Adaptability to Future Threats:
    > bcrypt’s design includes a cost factor that can be adjusted to increase the computational workload as hardware becomes more powerful. This ensures that the hashing process remains slow and secure over time. SHA-256, however, has a fixed speed that cannot be easily modified, potentially making it less effective against future brute-force attacks as computing power grows.
- Tailored for Password Storage:
    > The primary goal in password hashing is to protect sensitive data against unauthorized access, where security trumps speed. bcrypt is specifically engineered for this use case, making it an ideal choice. On the other hand, SHA-256 excels in applications requiring fast computation, such as verifying file integrity or supporting cryptographic protocols, but it’s not optimized for password protection.

Therefore, for applications like password storage where defending against brute-force attacks is critical, bcrypt’s deliberate slowness, built-in security mechanisms, and adaptability make it a superior choice over the faster but less specialized SHA-256.

### Question 4
A cryptographic hash function is designed with three primary properties in mind, preimage resistance, second preimage resistance and collision resistance.
1. **Preimage Resistance:**  
   - **Definition:** Given a hash output \( h \), it should be computationally infeasible to find any message \( m \) such that \( H(m) = h \).  
   - **Implications if Broken:**  
     If an attacker can invert the hash function (i.e., find an input for a given hash), they could potentially recover sensitive data from its hash, undermining confidentiality. For example, stored password hashes could be reversed to reveal the original passwords.

2. **Second Preimage Resistance:**  
   - **Definition:** For any given message \( m_1 \), it should be computationally infeasible to find a different message \( m_2 \) (where \( m_1 \neq m_2 \)) such that \( H(m_1) = H(m_2) \).  
   - **Implications if Broken:**  
     If an attacker can find a second preimage, they could replace a legitimate message with a fraudulent one without changing the hash. This undermines data integrity—if a digital signature is applied to the hash of a document, the attacker could substitute the document with a malicious version that has the same hash.

3. **Collision Resistance:**  
   - **Definition:** It should be computationally infeasible to find any two distinct messages \( m_1 \) and \( m_2 \) such that \( H(m_1) = H(m_2) \).  
   - **Implications if Broken:**  
     A collision allows an attacker to generate two different inputs with the same hash. This is particularly dangerous in scenarios like digital signatures, where an attacker might trick a signer into signing one document and then substitute it with another document that has the same hash, effectively forging a signature.

If any of these properties fail, the hash function loses its ability to securely provide authentication and integrity guarantees, opening up potential vulnerabilities in systems that rely on them for security.
